# 映词知识库维护源

这是映词桌面软件的只读知识库更新源。内容只有模型提示词规则、示例、许可说明和官方来源链接；不包含软件用户的需求、图片、账号、凭据或数据库。

`manifest.json` 提供当前维护版、更新说明、知识包下载地址及 SHA-256。`releases/` 中的版本文件发布后保持不变，客户端校验通过后才应用。知识库规则仅为声明式 JSON，不分发脚本或模型权重。

首个维护版包含 Codex 生图、Qwen-Image 2.1、FLUX 3 Image Klein、Fibo 2、Ideogram 4、MiniMax H3、LTX-2.5、Wan 2.2、Kandinsky 6。具体核对日期与来源见每份知识包；首次发布不会把原有资料标成今天重新核验。

## 发布维护版

1. 核对官方资料，修改 `catalog.json` 中对应知识包的内容及对应部分的版本（见下文）。
2. 修改 `release.json` 的维护版号与变更说明。
3. 运行 `python scripts/build-feed.py`，检查变更后提交。

仓库的发布工作流会校验内容并更新维护清单。历史版本保留在 `releases/`。映词客户端可选择手动更新、检查后提醒或自动更新；自动更新会保留用户自行同步或修改的知识库，并且不会调用生成模型。

## 推荐信息与规则独立版本

知识包保留必填 `packVersion`，新增可选 `recommendationVersion` 和 `rulesVersion`。推荐部分仅包含 `tag`、`order`；规则、示例、来源、核对日期、输出格式、名称及型号等其他内容归入规则部分。缺少某个新字段时，该部分版本回退使用 `packVersion`，已安装的旧包无需重写。

首次采用独立版本时，建议显式填写两个新字段，初值均为原 `packVersion`。例如三个版本字段原值都是 `2026.10.28.3`；只调整标签、排序时，仅将 `recommendationVersion` 改为 `2026.10.29.1`，`rulesVersion` 和 `packVersion` 保持原值。修改规则时只提升 `rulesVersion`。两个版本都不变的部分会被保留，不应在该部分夹带内容变更。

维护源仍提供完整知识包 JSON，沿用 `schemaVersion: 1`。客户端只合并版本变化的部分，对该部分的本地修改提示冲突；另一部分的本地内容和版本保留。旧格式维护包继续按整包更新。`manifest.releaseVersion` 是发布批次，仍需使用新批次并生成新校验和，不能修改已经发布的文件。

## 同系列模型换代

官方资料确认同系列后继型号时，复用原知识包 `id`，更新 `name`、`modelVersion`、规则、来源、核对日期并提升 `rulesVersion`。即使原 ID 包含旧型号数字（例如 `wan-2-2`），也保持 ID 稳定，现有草稿和选择会指向新版。无关系列使用独立 ID。推荐标签或排序需要跟随调整时，另行提升 `recommendationVersion`。

“同步官方资料”同样使用原 ID 替换当前型号，预览会提示换代关系；应用时保留最新推荐信息，也兼容旧应用已经生成但尚未应用的候选。被替换的完整包归档，可回退；历史任务继续使用提交时的快照，不迁移到新型号。

当前维护版2026.10.28.3含18份提示词知识库。新增目标仅用于编写提示词，不接入第三方图片或视频生成接口。独立 `gallery/manifest.json` 提供15个有署名案例及WebP预览，原示例型号和节选范围保留在条目中。
